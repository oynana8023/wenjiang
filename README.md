# 文匠 AI · 二创工作台

把一条链接，写成你的稿。移动端优先的静态 Web App，零后端依赖。`index.html` 是单文件自包含产物，可以直接部署到 GitHub Pages、添加到主屏幕当 App 用，也可以双击本地打开。

## 现在有什么

**真实数据，不造假**
- 热榜覆盖 10 个公开源：微博、知乎、头条、百度、抖音、B站、36氪、IT之家、极客公园、少数派。**全部走实时接口**：60s、codelife、36氪网关、少数派 API、极客公园 RSS，浏览器直连、带 CORS 头；同一个源多条通道并发竞速，每 60 秒自动刷新，时间精确到秒。只有当所有通道同时失败时才用缓存，并写明「缓存于」。
- 抓不到就显示抓不到，不会用编造内容填充。
- 时政、军事、外交类条目不进入榜单（不适合二创），页面上会写明过滤了多少条。
- 站内 12 篇示例素材一律标注 `示例素材 · 非真实新闻`，详情页顶部有黄条警告。

## v2.15：把「实时」这件事做实

上一版还在靠 GitHub Action 的快照兜底，这一版把快照彻底降级成最后一道保险。

**1. 十个源全部实时，没有一个是快照**

`api-hot.imsyy.top` 从 2026 年 11 月起长期 502，之前的「全快照」就是它拖垮的。现在每个源都换成了平台自己的接口：

| 源 | 实时通道 | 说明 |
|---|---|---|
| 微博 / 知乎 / 抖音 / 头条 | `60s.viki.moe/v2/*` + `api.codelife.cc` | 两条并发，谁先返回用谁 |
| 百度 | `60s/v2/baidu/hot` | 带摘要与封面 |
| B站 | `api.codelife.cc` | 60s 的 bili 接口 500，已换掉 |
| IT之家 | `60s/v2/it-news/rank` | 直接给 ithome 原文链接 |
| 36氪 | `gateway.36kr.com` 热榜 POST | 官网同款接口 |
| 极客公园 | 官网 RSS | 带 `access-control-allow-origin`，可直连 |
| 少数派 | 官网 API | 带 `access-control-allow-origin` |

抓取路径：全局 45 秒内存缓存 → 多条通道并发竞速（单条 7 秒硬超时）→ 全挂才读缓存。聚合镜像只在所有平台接口都失败后才试一次，且不再让它跟着并发发请求。

**2. 刷新是真刷新**

- 热榜页显示 `更新于 21:02:10 · 每分钟自动刷新`，精确到秒，骗不了人。
- 前台每 60 秒刷新当前这一屏；从后台切回来，如果数据超过 1 分钟立刻补一次。
- 手动「刷新」会清掉内存缓存再请求，保证拿到的是这一刻的值。
- 首屏不再用快照铺底：以前一打开先看到 15 分钟前的榜单，现在直接等实时，慢一点但不会看错。

**3. 二级页：缓存先铺，实时后换**

头条的帖子流接口只要请求里带 `Origin` 就 403（浏览器必带），所以必须过公共代理，而公共代理会限流、会慢到十几秒。现在的顺序是：

1. 点开话题，先用「本机上次实时抓到的」或「仓库缓存」把内容铺上，不让你对着骨架屏干等；
2. 同时发实时请求（头条走 `topic_innerflow` + 代理池，微博走解析服务），谁先回来换谁；
3. 本机每次实时成功都会存一份 30 分钟的本地缓存，同一个话题再看就是秒开，而且比仓库快照新；
4. 实时失败也不清空内容，只在下面加一条「这是 X 点的版本」+ 重试按钮。

微博这一条要说实话：它的搜索接口要访客 Cookie（`genvisitor2` 换 SUB），浏览器既拿不到也带不上，**没有解析服务就只能是缓存**。所以微博话题页会明确写这一句，并给「配一台解析服务（免费）」的按钮；头条不需要，它是直连 + 公共代理。

**4. 顺手瘦身**

构建时不再把 182KB 的话题正文内联进 `index.html`（从 769KB 降到 641KB），话题缓存改成点开时按需读 `data/hot.json`。开机也不再预下 200KB 的 `topics`，首屏更快。

## v2.14：把「点开一条热榜就有内容」做成默认能力

上一版修的是「连不上」，这一版修的是「点开没东西」。核心变化只有一句：**热榜的二级页不再依赖你自己配服务器**。

**1. 话题页真的有帖子了**

微博热搜和头条热榜给的都是「话题」，不是文章。以前点进去只有一个标题加一句「接口拿不到」，现在：

- 微博：走 `weibo.com/ajax/statuses/search`，用访客票（`genvisitor2`，不需要登录）取该话题下正在讨论的博文，带头像、时间、正文、配图、赞/评数。
- 头条：识别 `/trending/{id}/` 是话题页，走 `api.trending.topic` 取头图与阅读/讨论数，走 `topic_innerflow` 取话题下的微头条。
- 两者都由 `scripts/fetch-topics.mjs` 在 GitHub Action 里每 15 分钟抓一次，写进 `data/hot.json` 的 `topics` 字段（同目录读取，不存在跨域）。前端优先实时接口，没配服务就读这份快照，并标注「快照 · 时间」。
- 每条帖子点开是一个完整弹层，正文不截断、图片原样列出，可以直接「用这条写」——不再需要先解析一次原帖。

**2. 没图就不占位**

以前没有头图会画一块白底占位，在手机上就是一大片空白。现在封面容器默认是空的：拿到真实图片才插入，拿不到就什么都不显示。图片加载失败会自己移除，不留破图标。

**3. 解析线路内置三条公共通道**

不配置也能试：Jina Reader、AllOrigins、CodeTabs 三条公共阅读线路并发竞速，12 秒硬预算。它们不受我们控制，会限流、会下线，所以只当兜底；要稳定还是配一台 Worker（页面里有一键部署）。失败时的提示改成「公共线路这次都没通」，并给出「配服务 / 粘全文」两条路，不再把锅甩给链接。

**4. 模型：零配置也能写**

- 新增「内置免费通道」：Pollinations（`text.pollinations.ai/openai`，不需要 Key）+ LLM7（`api.llm7.io/v1`，Key 固定填 `unused`）。两家都允许浏览器直连，不需要任何中转。
- 「我的 → 模型服务」在没接服务商时直接给一个「一键启用内置免费通道」按钮，点一下就写入两条服务商并设为默认；主通道限流会自动切备线。
- NVIDIA NIM 这类厂商**不给浏览器发 CORS 头**，直连必然失败，这不是 Key 的问题。现在获取模型失败时会直接说清原因，并给「先用内置免费通道」的出口；有解析服务（或同源 Node 实例）时自动经 `/api/llm` 中转，Key 不落库。

**5. 热榜快照更小、更稳**

`data/hot.json` 改为压缩输出，并合并二级页内容（热榜 61KB + 话题 ≈200KB），头条分享链接里的 `log_pb` 等埋点参数被去掉；抓取链路加入 60s / codelife 两家镜像，官方接口抽风时快照仍能更新。

## v2.13：一次完整的体检与修复

这一版没有加新板块，只做一件事——把上一版弄坏的地方修回来，并把「没配解析服务」这条最常走的路铺平。

**修掉的问题**

1. **解析服务连不上**：v2.12 里内置了一个沙箱临时域名当默认解析地址，域名下线后，所有没配过地址的用户都会卡在 12 秒超时，然后报「解析失败」。现在默认不内置任何地址：没配就直说「还没配」，并给出一键部署 Worker 的入口（Cloudflare 免费，约 1 分钟）。贴链接失败从 6 秒降到 70 毫秒，不再让人干等。
2. **热榜全是快照**：原来只依赖一个公共聚合接口（`api-hot.imsyy.top`），它挂了以后静态页只能读仓库快照。现在改成多源竞速：60s（微博/知乎/抖音/头条）、codelife（微博/知乎/B站/抖音）、少数派官方接口、老接口依次尝试，单源 7 秒预算，谁先返回用谁。实测静态托管下 10 个源里 6 个能实时，其余 4 个显示「快照」并标出快照时间。
3. **写了 30–39 字被弹回**：新建页允许 30 字，生成时却按 40 字卡，用户点生成直接被退回，还以为是模型坏了。现在两个门槛对齐：粘贴正文 30 字、解析出的网页正文 40 字，太短就在原地提示补几句。
4. **「实际保留 350%」**：成稿比原文长时保留率会超过 100%，看不懂。现在封顶 100%，超过 105% 另注「成稿比原文长，属扩写」。
5. **示例任务打不开**：以前「用示例任务」必须联网解析活动页，没配服务或断网就报错。现在内置了那份公开活动原文（1.5k 字），双击 HTML 也能从拆任务一路走到成稿。
6. **模型乱回 JSON 被当评论**：评论生成偶尔拿到 `{"ok":true}` 这类内容，会被当成一条评论显示。现在过滤掉 JSON/ok 这类非评论文本，退回本机引擎重写。
7. 弹层补了 Esc 关闭；解析服务面板改成「一键部署」+ 命令行两种方式，并明确写清接口契约；「我的」里解析服务未配置时用黄色标出。

**验证方式**

三套环境各跑一遍端到端（本地 Node 服务、纯静态 HTTP、`file://` 双击）：热榜首屏、10 个源切换、链接解析、文字改写、双素材、评论、创作全流程（拆任务→取证→成稿）、作品库、解析设置、主题切换、320/360/390/430 四档宽度布局。改写引擎另跑 60 组平台×素材组合与长稿多字数档测试。

## 内容创作：接任务，写原创（v2.12 新增）

底部导航第三格「创作」。它和「改写」是两条完全不同的路：改写是把别人的稿子重排一遍，创作是先拆任务、再联网查证、然后自己写。不换同义词，也不编数字。

**流程**

1. **贴活动帖**：网易小蜜蜂、抖音、小红书、今日头条、微博、公众号的活动页都能读（走你自己的解析服务）。读不到会给出「粘贴正文」的入口，不让你卡在这一步。
2. **拆任务**：把帖子拆成「参与方式 / 截止时间 / 必带话题 / 奖项 / 硬性要求」。一条活动常有多玩法（例如小蜜蜂两周年：作品投稿、互动游戏、评论区祝福），会列成可多选的卡片；拆错了点「手动改」，标题、截止、话题、要求都能直接编辑。
3. **联网取证**：用任务关键词生成 3–4 组检索词，走 `/api/search` 找公开网页，列出标题、站点、日期、摘要和相关度。默认只勾选相关度 ≥34% 的条目，其余列出来但不勾——**交给用户判断，不把无关网页塞给模型**。也可以贴一篇你找到的报道链接，或只用自己拍的素材。
4. **写原创**：模型只拿到「勾选的资料 + 你上传的素材 + 任务要求」。提示词里写死了三条：数字/日期/名额必须能在资料里找到；不得连续 12 字照搬资料；没有真实经历就写「我看到的」，不许编亲历细节。
5. **成稿与核对**：成稿页逐条列出「哪句话来自哪条资料」，正文里每个数字都单独标出来，对不上的标黄并说明。发布清单按任务要求自动勾选（话题、字数、截止、AI 标识）。

**读图与读视频**

- 图片：压缩到 1024px 后交给识图模型，描述场景、人物、物品和画面文字，写稿时当作「我拍的这张图里有什么」。
- 视频：浏览器里抽 4 帧（12%/36%/60%/84%），逐帧识图，把画面描述带进提示词。不上传原视频，也不做语音转写。
- 没有识图模型时，图片只作配图，不参与写作，界面会明确提示。

**检索通道**

`/api/search` 是新加的接口（Worker 3.5.0 / `server.js` 同步支持）：把必应结果页抓回来解析成结构化条目，中文长尾词再补一路搜狗微信，按「检索词二元组覆盖率」重排，滤掉「小蜜蜂 → 小游戏」这类单字误匹配。老版解析服务没有这个接口时，会自动退回「把必应结果页当普通网页抓」的文本模式（能拿到摘要，拿不到链接）。

> 升级方式：「我的 → 解析服务」里那条 Worker 重新部署一次（`cd worker && npx wrangler deploy`，或在 Cloudflare 控制台重新 Deploy）。不升级也能用，只是证据卡片少了原文链接。

**三条底线**

不编造数字与亲历细节；不整段照搬资料；不承诺收益、不用「最/第一/唯一」这类绝对化说法。查不到资料时，界面会让你贴链接或只用素材写，而不是让模型硬编。

**链接解析怎么才能成功**

浏览器受同源策略限制，读不了别人的网页；「贴链接取正文」必须有一台服务器代抓。所以解析能力 = 你手上有多少条服务端通道。现在有三层：

1. **同源服务**：页面本身由 `node server.js` 托管时，零跨域，最快。
2. **自建 / 云端服务（主力）**：`worker/index.js` 是 Cloudflare Worker 版，一键部署后就是**永久属于你自己的解析地址**（免费额度每天 10 万次）。「我的 → 解析服务」可以填多个地址，解析时**并行竞速**，谁先返回合格正文用谁，某一条挂了不影响其他。**不再预置任何云端默认实例**：之前那个沙箱地址下线后，没配过地址的用户会卡在 12 秒超时上（解析用不了、热榜也被拖到只能读快照）。现在没配就是没配，界面会直接提示并给出一键部署入口。
3. **公共代理**：只剩 3 条，能通的越来越少，仅作兜底。

「我的 → 解析服务 → 保存并检测」会把每条通道的在线状态和延迟列出来：绿色 `在线 · xx ms` 说明这条能用，红色会写明为什么连不上。

实测 2026-11-19：公众号（mp.weixin.qq.com）4239 字 / 2182 字、IT之家 310 字、少数派 1129 字、极客公园 5939 字，均能取到正文；36氪、知乎、微博搜索页取不到（前两个是 JS 渲染 + 风控，微博热搜给的是搜索页而不是文章）。

### 三分钟上线自己的解析服务

1. 打开 <https://deploy.workers.cloudflare.com/?url=https://github.com/oynana8023/wenjiang/tree/main/worker>
2. 用 GitHub / 邮箱登录 Cloudflare（免费，不需要信用卡）→ 点 **Deploy**
3. 拿到 `https://wenjiang-parse.xxx.workers.dev`，打开 App →「我的 → 解析服务」→ 粘进去 → **保存并检测**

想在改代码后自动重新部署，就往仓库 Secrets 里加 `CF_API_TOKEN` 和 `CF_ACCOUNT_ID`，`.github/workflows/deploy-worker.yml` 会在 `worker/` 有改动时自动发布。细节见 `worker/README.md`。

### 部署自检：两个东西别搞混

这个项目有**两套彼此独立的部署**，谁也替代不了谁：

| 部署 | 托管什么 | 地址长什么样 | 挂了会怎样 |
| --- | --- | --- | --- |
| GitHub Pages | 整个 App（`index.html`） | `https://oynana8023.github.io/wenjiang/` | 打不开 App |
| Cloudflare Worker | 只有解析接口（`/api/parse`、`/api/meta`） | `https://wenjiang.xxx.workers.dev` | App 能开，但「解析」只能走公共代理，成功率低 |

云端的 Worker 页面打开是一片 JSON 或说明页，**这是正常的**——它是给 App 调的接口，不是网页。

在 Cloudflare 后台「Workers 和 Pages → wenjiang → 部署」里，判断是否真的上线只看两个数：

- **流量百分比 100%**：当前版本在接流量。显示 `0%` 说明版本只是上传了、没切流量，等于没生效。
- **调用次数**：App 里填了这个地址并点过「保存并检测」，这里才会有数。一直是 0 说明没人调它。

看 `流量百分比 0%` 时，八成是这两处配置不对，去 **Settings → 构建** 改：

1. **Root directory（根目录）**：留空，指向仓库根目录。填成 `worker` 会让 `name` 对不上，构建直接报 `must match your Worker name`。
2. **Deploy command（部署命令）**：`npx wrangler deploy`。若被改成 `npx wrangler versions upload`，就只会产生一个 0% 的版本。

改完点 **Deployments → 重新部署**（或随便推一次提交）。成功的标志是：版本变成 `100%`，并且下面这行能返回 JSON：

```bash
curl "https://wenjiang.<你的子域>.workers.dev/api/health"
# {"ok":true,"version":"3.0.0","runtime":"worker"}
```

再验证真能取正文：

```bash
curl "https://wenjiang.<你的子域>.workers.dev/api/parse?url=https%3A%2F%2Fsspai.com%2Fpost%2F119191"
```

拿到 `{"ok":true,"chars":1129,...}` 之后，把它填进 App 的「我的 → 解析服务 → 新增一条」→ **保存并检测**，看到绿色 `在线 · xx ms` 就算彻底通了。

**链路**
1. 找选题：首页/热榜页点一条，弹层里直接给出**分类、发布时间、站点作者、头图与摘要**（从原文页的 og / JSON-LD / 公众号 `var ct` 读出来），下面是原文链接，可以一键打开、一键复制、一键解析正文；榜单只给搜索页的源（微博/百度/抖音）会明说「这条没法直接解析」。
2. 取正文：同源服务、配置的解析服务、公共代理**同时开跑，谁先拿到合格正文就用谁**（不再一条条排队）；服务返回 502（实例重启）会自动等 3 秒重跑一轮；全失败时把每条通道的原因逐行列出，并给「再试一次 / 复制链接 / 用浏览器打开 / 改成粘贴全文」。公众号正文按 `#js_content` 单独抽取，被微信拦住会直说是被拦。
3. 改写：6 种风格 × 3 档强度 × 6 个平台，支持自定义要求、去 AI 味、事实保真。
4. 自检：改写幅度、重合率（连续 12 字以上）、重复句数，全部本机计算。
5. 配图：**优先用原文里的真实图片**（取 og:image 与正文配图，按文件去重、按尺寸过滤掉 1px 占位图），点「设为封面」直接进成稿，来源标为「原文配图」；确实没有可用图，才用出图模型生成，或给三张提示词（3:4 / 16:9 / 1:1）复制到即梦、豆包、MJ。
6. 归档：作品存本地，可回看、复制、导出 Markdown。

**外观**
- 三档：跟随系统 / 深色 / 浅色。默认跟随系统，白天自动浅色，不用手动切。入口在「我的 → 外观」，右上角图标也能直进。

**公众号**
- 微信不提供公开的公众号热文榜，市面上号称「公众号热榜」的多是二手数据。所以这里不谈榜单，只做「贴链接取正文」，热榜页底部有直接入口。

**模型配置：可以接好几家**
- 每一家填 Base URL + Key，点「连接并获取可用模型」读 `/models`，每个模型自动标注 `看图` `出图` `推理` `快` `大`，并给一句「擅长什么」（按 GPT / Claude / Gemini / DeepSeek / Qwen / GLM / Kimi / 豆包 等家族匹配）。
- 设一个**默认服务商**，其余按添加顺序排队。生成时默认那家超时、限流（429）或 Key 失效，自动换下一家，界面上会提示「已自动切到 X」；全都调不通才退回本机引擎，不会把人卡在报错页。

- **出图模型**在服务商里勾选。配了多家时，配图会自动挑一家能出图的；一家都没有就只给提示词，并用 3 秒提示说明，不弹框打断。

## 模型配置（v2.5 重做）

接自己的模型时最容易踩的三个坑，这一版都处理掉了：

**1. 地址不是都叫 `/v1`。** 智谱是 `https://open.bigmodel.cn/api/paas/v4`，阿里百炼是 `/compatible-mode/v1`，火山方舟是 `/api/v3`，NVIDIA 是 `/v1`，OpenRouter 是 `/api/v1`。以前只填域名会被一律补成 `/v1`，请求必然 404，看起来就像「配好了却用不了」。现在内置 11 家常用服务商，点一下填好地址；只填域名也会按厂商自动补齐路径。

**2. 一次拉回四五百个模型，能用的只有十几个。** `/models` 会把向量、重排、语音、审核、视频模型全塞给你，还有一堆要额外充值才有权限。现在拉完会先按名字和厂商返回的元数据分成「文案 / 出图 / 其他」三栏，其他栏默认不参与测试；点「试前 20 / 全测一遍」会**真发一条 4 个 token 的对话**，只有返回正常才算可用：

| 标记 | 含义 | 处理 |
| --- | --- | --- |
| 可用 | 真调通，有返回 | 保留，自动选为默认 |
| 要付费 | 402 / 余额不足 / 未开通 | 标红，不参与自动选 |
| 无此模型 | 404 / 模型不存在 | 标红，不参与自动选 |
| Key 无效 | 整批 401/403 | 提示检查 Key，并擦掉误标 |
| 限流 / 超时 | 429 / 超时 | 保留，可重试 |

出图模型是**竖向列表**，可以单独「试」：只发空 prompt 做存在性探测，模型存在会回「prompt 不能为空」，不存在才回 model not found —— 不会真的生成图片扣钱。

**3. NVIDIA 这类厂商根本不让浏览器直连。** `integrate.api.nvidia.com` 不返回 `Access-Control-Allow-Origin`，浏览器一定拦。现在模型请求先直连，跨域失败会自动走**解析服务的中转** `POST /api/llm`（Node 与 Worker 两版都实现了，只放行 `/models`、`/chat/completions`、`/images/generations` 等固定路径，拒绝内网地址，Key 只在这一次请求里带上）。「我的 → 模型服务商 → 跨域中转设置」可以指定自己的 Worker。实测：静态托管页面经云端中转拉 NVIDIA 33 个模型，约 2 秒。

另外：智谱的 `glm-4-flash / glm-4v-flash / glm-4.5-flash / glm-z1-flash / cogview-3-flash` 经常不在 `/models` 里，现在会作为「内置免费型号」补进列表，标成待验证，点测试才知道真伪；手动填写的模型名会立刻试一次，不能用的当场说明原因，不会再出现「加了但不知道为什么不生效」。新加的服务商会自动设为默认，避免「配好了却还在用旧的那家」。

## 这一版（v2.11）：字数由你定，不再按平台把长稿压成摘要

**1. 以前是平台替用户决定写多长，这是错的。** 旧逻辑里，目标字数 = 平台区间（小红书 300–600、头条 700–1200），再按素材长度夹一次。一篇 5000 字的深度稿发小红书，就被压到 300 字，人物来历、时间线、因果链全没了，读者不知道「这个人是怎么来的」。现在平台区间只作提示，字数由用户在新建页自己选：

| 选项 | 适用 |
| --- | --- |
| 跟原文 | 长稿保留一半以上，短稿不注水（默认） |
| 600 / 1200 / 2000 / 3000 字 | 选多少写多少，超长素材也能落在这个字数 |

选完之后，成稿页会明确写「原文 4830 字 · 目标 2000 字 · 实际保留 41%」，不再是黑箱。原文撑不起所选字数时（比如 250 字素材选 3000 字），会写明「原文只够 320 字」，写满素材为止，不编造、不注水。

**2. 取料从「摘最精彩的几句」改成「按预算覆盖全文」。** 旧逻辑每个结构固定取 3–5 句，5000 字的稿子只用开头，后面 90% 的料全废。现在按目标字数换算出「要写多少句」（`budget = 目标字数 ÷ 原文平均句长`），再把原文切成分段，每段取信息量最大的连续两三句：

- 连续取，不隔句跳。人物的第一次出场、他为什么在这里、后来发生了什么，通常在同一段里，隔句摘就会挑断。
- 分段取，保证覆盖到结尾，不会只写开头。
- 摘块末尾如果是「行业里的判断也在变。」这种总起句，直接丢掉，不留半句话悬着。

长句也不再一刀切到 34 字。目标 600 字时单句留 58 字，2000 字留 88 字，3000 字留 130 字——句子该多长，由篇幅决定，不是一律砍半。

**3. AI 提示词增加【篇幅】段，优先级高于平台区间。** 明确写「原文 X 字，这次写成 Y 字左右（约原文的 Z%）」，并要求：压缩的是句子不是信息，谁、什么时候、做了什么、为什么、结果如何这五样必须留着；不要逐句换同义词交差，按自己的叙述顺序重排；长稿分 3–5 节，每节一个小标题。写完的自检也改成按目标字数判断（±30%），不再拿平台区间卡一篇 2000 字的长稿。

**4. 顺手修掉了几处会在长稿里放大的毛病。** 同义词表里「标准→尺度」「市场→盘子」「开始→启动」「报告→统计」「实际→落地」这几对会造出「车规尺度」「盘子上」「现在启动学着看」这种病句，已删除；断句不再切在冒号后面（「算了笔账：/ 如果良率…」），也不把「2024 年 6 月。」单独成句；「数字也能说明问题：」只在句子真有数据时才出现；「把 A 和 A 放在一起看」这种重复拼接，在缺第二关键词时换成不带对比的说法。

## 上一版（v2.10）：长链接能解析了，三张图三个机位，复制出去不再带井号

**1. 一个 240 字的判断，把所有长链接挡在了解析之外。** 「先解析看看」能出正文，直接点「开始改写」却提示「素材太短」——原因是 `resolveSource()` 里写着「链接短于 240 字才去解析」，而公众号、小蜜蜂、头条的分享链接带着 `spss/utm/chksm` 一长串参数，基本都超过 240 字，于是被当成空素材。现在只认有没有 `http`，长度不再参与判断。

顺手补了三处：链接里的 `&amp;`、零宽字符、末尾粘上的句号会被清掉（以前会让服务端 404）；整条链失败后，自动去掉跟踪参数再取一次（正文只跟路径里的 ID 有关）；链接框里没有 http 但粘了长正文时，直接按「粘贴全文」处理。取到的正文不足 40 字，不再只说「素材太短」，而是给出字数和原因，并直接提供「改成粘贴全文」的出口。

**2. 三张图只换画幅不换机位，模型当然给三张一样的图。** 以前封面、头图、方图共用同一个主体和同一个场景，区别只有比例和镜头参数，出图结果自然是同一张图裁三次。现在拆成三个机位：

| 机位 | 拍什么 | 主体 | 镜头 |
| --- | --- | --- | --- |
| 封面 · 竖版 | 主体撑满，环境只做虚化背景 | 文中认出的实物 | 85mm，f/2.0 |
| 头图 · 横版 | 退到广角，讲清「在哪、和什么在一起」 | 场景本身，实物偏左且变小 | 24mm，f/4 |
| 细节 · 方图 | 贴近拍材质、接缝、标签 | 陪衬物，或主体的局部 | 100mm 微距 |

三张的「画的是」、原文关键词、自检词（用于识图核对）也各自独立，不再互相顶替。同时补了港口集装箱、货轮、光伏板、药瓶、住宅楼、金条、舞台、游戏手柄、外套等高频物件，以及港口场景，供应链、光伏、医药、楼市这类稿子不会再一律画成车间传送带。

**3. 正文里的井号，是模型把 markdown 当成了排版。** 模型偶尔写「### 优点」「* 第一条」，页面原样显示，复制到头条、小红书、公众号编辑器里也是一串井号加星号，用户还得逐行删。现在：`###` 及以上统一收成 `##`；头条、小红书、抖音这些不需要小标题的平台，直接把 `##` 去掉；渲染层一到六级标题都认，有序列表按真数字排；「复制全文」「导出」走纯文本，井号和星号一律清掉，但 `#话题标签` 的井号保留。标签仍然单独存字段，按平台需要的数量追加到正文末尾（小红书 4 个、微博 2 个、酷安 1 个），复制时不会漏。

酷安不能写成「姐妹们冲」，小红书不能写「综上所述」，公众号不能写成口播稿——这些不是靠一句「注意平台风格」能解决的，所以每个平台都写死了读者、结构、标题、语气、禁忌五项，AI 提示词和本机引擎共用同一份配置（`engine.js` 里的 `PLAT`），不会两边各写一套越走越偏。

**4. 本机引擎补上「褒贬切分」，不再所有平台共用一套骨架。** 新增 `review`（酷安）和 `buzz`（小蜜蜂）两种结构，会先把素材里的句子分成正面、负面、中性三类，再按平台取用：酷安要「3 优点 + 2 槽点 + 谁该买」，小蜜蜂要「打分 + 观察 + 最想吐槽的 + 提问」。同一篇稿子切到不同平台，出来的是不同结构，不是同一段话改几个词。

**5. 去掉了几处典型的机器味。** 删掉硬塞的「再看一层，」过渡句；分点里不再以「更关键的是，」开头；修复「打价格战」被替换成「打售价战」、「订单量」被替换成「单量量」、「品牌」变「牌子」这类破坏固定搭配的替换；长句断句找不到标点时宁可整句保留，不再切出「变成了消费。」这种残句；公众号导语不再因为去重逻辑把首句吞掉。

## 上一版（v2.8）：类目按分数定，画面和稿子对得上

**1. 类目不再「谁排在前面谁赢」。** 之前是一个正则列表从前往后试，第一个命中就定终身。一篇讲腾讯告百度的稿子，正文里出现一次「经济损失」，就整篇进了财经类，最后画成一栋写字楼；更早那版甚至画成车间里的传送带。现在改成计分：**标题命中算 4 分，正文每命中一次算 1 分**，取总分最高的类目。同一篇稿子里「法院、判决、侵权、开庭、索赔」会出现十几次，「经济损失」只出现一次——分数一比就知道该画法庭。

**2. 补上法律类目。** 以前词表里根本没有法院、诉讼这一档，讲官司的稿子只能被就近塞进财经或办公类。现在新增 `law`：主体是「一把木质法槌，锤头有使用痕迹，压在深色台面的文件上」，场景是法庭内部，自检词是「法槌」。商标、专利、著作权、反垄断、行政处罚、约谈也都归到这一档。

**3. 场景必须和主体讲得通。** 场景表加了 `only` 白名单：车间只对工厂、产线、酒水、食品、科技硬件开放，法庭只对法律类开放。以前是「谁命中次数多就用谁」，于是会出现「主体是法槌、背景是传送带」这种拼贴；现在命中了但不兼容，直接当没命中。

**4. 「发布公告」不再等于发布会。** 事件词表里 `发布` 加了否定前瞻，`发布公告 / 发布声明 / 发布财报 / 发布通报` 不再触发「新品发布舞台」。这条是上一篇稿子画错的直接原因之一。

**5. 关键词依据摆出来。** 每张提示词卡在「画的是：一把法槌 · 法庭」下面多一行「原文关键词：索赔 · 法院 · 起诉 · 开庭」，生成后的图上也会写「取自原文「索赔/法院/起诉」」。为什么画这个、依据是哪几个词，一眼能查；不对，你直接指出来，我改词表就行，不用再猜。

## 上一版（v2.7）：提示词与成图对得上

**1. 提示词不再写「事件」，只写「画面」。** 上一版把标题前 22 字直接当主体，于是「华为星芒 OSTA01 Pro 价格公布」变成一句 `画面主体：华为星芒 OSTA01 Pro 价格公布`——这不是能画的东西，模型只能按「科技」两个字自由发挥，给一张机械臂加电路板的赛博图，跟稿子毫无关系。更早那一版更离谱：一篇讲荔枝冰酒的稿子，被「消费者」「订单量」几个词带进财经类，画出一块折线屏幕。

现在的顺序是**先从正文抠实物，再谈风格**。词典里收了七十多个具体物件（酒瓶、荔枝、玻璃瓶、纸箱、手机、芯片、机器人、传票…），标题命中加权，取权重最高的当主体，同组的第二个当陪衬，拼成「一瓶琥珀色酒液的玻璃酒瓶，旁边几颗带壳的新鲜荔枝」。场景同样从文里读：通篇写「生产线、缺瓶、加班加点」就画灌装车间，写「欢迎晚宴」才画宴会桌；多个场景同时出现按**命中次数**定，一句「晚宴」压不过十次「生产线」。没有实物可抠时才退回可视类目模板。品牌名、型号编码一律不进画面，否则模型会去画 logo、拼错字。

**2. 中英双版 + 机位参数。** 出图走英文（`a flagship smartphone standing upright, triple camera module...`），展示和复制走中文；三个画幅各有尺寸（864×1152 / 1344×768 / 1024×1024，厂商不认这个尺寸就自动降到方图，再不行就不传 size）、镜头（85mm f/2.0 / 35mm f/2.8 / 100mm macro）、构图与留白位置，末尾统一挂 `no text, no letters, no logo, no collage`。提示词卡上先给一句「画的是：一部深色旗舰手机 · 新品发布舞台」，对不对一眼能看出来；完整提示词折叠在下面，中英文各一个复制键。

**3. 出图模型必须真画得出来。** 之前只看模型名里有没有 `image`，把 `glm-4v-flash` 这类识图模型也当成出图模型——点生成必然失败，或者落到别家画出一张不相干的图。现在识图模型（`vision / -vl / 4v / 4o / omni`）不进自动推荐，旧配置里选错的会在启动时换成同家的出图模型并写明原因；出图模型的「可用」也改成真画一张 1024 的小图来验，返回空图不算通过。名字像识图模型但没别的可换时不会硬删——有些聚合网关什么名字都能出图，让它真画一次再定生死，正规厂商则会在报错里说清楚「这是识图模型」。

**4. 出图后自动核对，跑偏就重画。** 有识图模型时，生成完先问一句「图里最突出的东西是不是手机」，答否就换更简单的纯净背景重画一次；重画通过就用新的，仍不通过就保留原图并明确标「没画准，建议重生成」——不假装没问题。没有识图模型时标「无法自检」，不冒充已核对。生成区第一张按真实比例展示（3:4 不再被裁成方块），下面注明依据哪张提示词、是否重画过，还能展开看这张图实际用的提示词。

## 上一版（v2.6）：话题二级页、原文配图、真评论

**1. 微博热搜不再是「一锅乱炖」。** 热搜点进去是一个话题，话题下面是几十条不同人发的帖子，以前把几条各截一半拼成素材，二创必然跑偏。现在点开热榜会先列出**这个话题下的原文**：作者、字数、正文摘要、配图，挑一条完整的再解析。点「查看全部」进第二层，里面是完整清单。每条微博都会补全「全文」——`statuses/extend` 拿不到时直接回查单条接口，不再停在「…全文」。

**2. 原文配图能取到了。** 两个原因：一是解析接口只回文字、不回图片；二是懒加载站点的 `src` 是 1px 占位图，真图在 `data-original` 里，旧代码按 `src|data-original` 的先后匹配，永远先命中占位图。现在解析结果自带 `images`（og:image + 正文懒加载图 + 平台内嵌 JSON 的图集），创作页点「先解析看看」就能看到标题、字数和缩略图；成稿页的「原文配图」直接用解析阶段抓到的图，不再依赖第二次抓页面。微博图床经 `/api/img` 同源转发。

**3. 平台专项解析。** 小红书笔记、抖音视频、小蜜蜂正文都不在 `<p>` 里，而是塞在 `__INITIAL_STATE__` / `_ROUTER_DATA` / JSON-LD 里。现在会先把这些内嵌 JSON 挖出来，取标题、正文、图集；视频页额外取文案与字幕（有 `.vtt/.srt` 就把口播转成文字，没有就如实说明「只有作者文案，口播转写不了」）。死链单独识别：小蜜蜂、小红书这类「内容不存在或已被删除」的页面会直接说清楚是链接过期或作者删除，不再含糊成「正文太短」。

**4. 「可用」= 真的能写出东西。** 以前探测只发「在吗」、4 个 token，只要能回一个字就标可用，看着能用、生成时却掉链子。现在每个模型都要按题目写一句 18–30 字的中文，写不成句、空返回、要充值、没权限、无此模型的一律剔除。默认只显示可用和待测，确认不能用的收进「已剔除」，可以一键「彻底删掉」。列表改成状态点 + 模型名 + 一行说明，工具条横滑不换行。

**5. 评论有两条路。** 一是二创完成后，成稿页点「读者会怎么评」，生成 3 条模拟读者评论，逐条或全部复制；二是首页「写条评论」，贴链接或正文，跳过二创直接出评论（2/4/6 条，真诚/犀利/补充内情三种口气）。本机引擎按「一条只说一件事 + 必须带原文细节」来写；接了模型则按同一套规则让模型写，禁止「首先/总之/不得不说」这类腔调。

## 目录

```
src/index.tpl.html      页面骨架模板（构建用，不要直接打开）
build.mjs               把模板 + CSS + JS + 热榜快照打成单文件 index.html
index.html              构建产物：单文件，双击就能跑，也是 GitHub Pages 的入口
assets/css/app.css      设计系统（深色优先，纸白可选）
assets/js/data.js       词库与 12 篇示例素材
assets/js/engine.js     本机改写引擎 + 配图提示词生成
assets/js/live.js       热榜 / 链接解析 / 模型 / 出图
assets/js/ui.js         视图渲染
assets/js/app.js        状态、路由、事件
scripts/fetch-hot.mjs   抓热榜，写 data/hot.json
data/hot.json           热榜快照（由 Action 每 15 分钟刷新）
server.js               可选：本地静态服务 + 后端代理
worker/index.js         解析服务（Cloudflare Worker 版，单文件零依赖）
worker/wrangler.toml    Worker 部署配置（在 worker/ 目录里单独部署时用）
wrangler.toml           仓库根目录的 Cloudflare 配置（后台「连接 Git」部署时用）
.github/workflows/hot.yml
.github/workflows/deploy-worker.yml
```

改完 `assets/` 或 `src/` 里的文件，跑一次 `node build.mjs` 重新生成 `index.html`。

## 部署

### 方式 0：一条命令推到 GitHub（需要 token）

```bash
GH_TOKEN=github_pat_xxx node scripts/deploy.mjs
```

脚本会：校验 token → 建仓库（已存在就复用）→ 推送 → 打开 Pages → 等构建 → 打印网址。
可选：`REPO=名字`、`VISIBILITY=private`、`SKIP_WORKFLOW=1`（token 没有 Workflows 权限时用）、`DRY=1`（只检查不推送）。

Token 用 fine-grained 的，只勾这一个仓库，权限给 **Contents: Read and write**、**Pages: Read and write**、**Workflows: Read and write**，有效期 7 天。

### 方式 A：网页上传（不需要任何凭据）

要传的文件只有 5 个，全部在仓库根目录：

```
index.html              必需，整个应用都在里面
manifest.webmanifest    安装成 App 用（可选但建议）
sw.js                   断网可用（可选但建议）
icon.svg                图标
icon-512.png            图标（iOS 主屏幕用）
```

1. GitHub 网页 → New repository → 名字例如 `wenjiang` → **Public** → Create repository。
2. 仓库页 → Add file → **Upload files** → 一次选这 5 个文件 → Commit changes。
3. Settings → Pages → Source 选 `Deploy from a branch`，分支 `main`、目录 `/ (root)` → Save。
4. 等 1 分钟，访问 `https://<你的用户名>.github.io/wenjiang/`。
5. 手机上用 Safari / Chrome 打开 → 分享 → 添加到主屏幕，就是一个全屏 App。

只传 `index.html` 也能跑，只是没有离线缓存和 Android 的「安装应用」入口。

这样部署出来的站点热榜显示为 `快照`（内联的那一份，页面会标出抓取时间）；联网正常时会先尝试实时接口，成功就显示 `实时`。

### 方式 B：整仓库部署（热榜能自动刷新）

把仓库完整推上去（含 `data/hot.json` 和 `.github/workflows/hot.yml`），Pages 设置同方式 A。

热榜快照由 Action 每 15 分钟抓一次并提交，不需要任何密钥。首次部署后去 Actions 页手动跑一次 `refresh-hot`，`data/hot.json` 就有内容。

> 没有后端时，热榜会先尝试浏览器直连公共聚合接口（有 CORS），失败再退回仓库里的快照。链接解析走阅读器代理链，公众号成功率不如自建后端。

### 它已经是一个 PWA

仓库里带了 `manifest.webmanifest` 和 `sw.js`：在 GitHub Pages（https）打开后，Safari「分享 → 添加到主屏幕」或 Chrome「安装应用」，就是一个全屏、无地址栏、断网也能打开的独立 App。入口也在「我的 → 装到主屏幕」。
单文件上传（方式 A）时没有 `sw.js`，iOS 仍能添加到主屏幕，但断网打不开。

### 关于白屏

以前把 `index.html` 单独下载下来只有两行字，是因为旧版本的页面骨架里引用了同目录的 `assets/`，单独一个文件当然加载不到。现在 `index.html` 是构建产物，这个问题不存在了；如果哪天真白屏，页面会在 2.5 秒后自己提示原因，不会留一片黑。

### 本地 / 自建（有后端，效果最好）

```bash
node build.mjs && node server.js   # http://localhost:3000
```

自带 `/api/health`、`/api/hot`、`/api/parse`。前端启动时会探测 `/api/health`，有后端就优先用它，链接解析和热榜都走同源，没有跨域问题。

放在自己机器上长期跑，用 pm2 守着（崩了自动拉起，重启机器后 `pm2 resurrect` 恢复）：

```bash
npm i -g pm2
PORT=3000 pm2 start server.js --name wenjiang
pm2 save
```

## 关于「原创度」

没有做「原创度评分」这种无法验证的东西。页面上是两个可核对的数字：

- **改写幅度** = 输出里连续 12 字以上片段与原文不重合的比例
- **重合率** = 上述重合片段占全文的比例

同一套算法算出来的，加起来是 100。它们和平台判定不是一回事，页面上也这么写。

本机引擎是规则驱动的（同义词替换 + 长句拆分 + 段落重排 + 语体适配），短稿能做到 60–90% 幅度，长稿会明显偏低——所以界面上会直接告诉你「长文建议接模型」。接了大模型并走 AI 路径，改写幅度由模型决定。

## 合规边界

- 不承诺「过原创检测」，不做同义词替换式洗稿的营销话术。
- AI 生成内容默认在复制时附带声明（可在「我的」关闭），对应 2025 年 9 月施行的《人工智能生成合成内容标识办法》。
- 深度改写的定义是重排结构、换视角、补信息，不是改几个词。

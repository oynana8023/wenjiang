一、先说结论

你这次的两条反馈，都是真的，而且都能定位到具体代码：

1. 热榜不是"偶尔旧"，是三个 bug 叠在一起：抖音榜取的是微信的榜单 id、B 站榜取的是百度的榜单 id（所以点抖音看到的像公众号文章）；主力通道 60s.viki.moe 在国内被 Cloudflare 整片限流；data/hot.json 又被 Service Worker 写成"缓存优先"，装到主屏后永远先交上次那份。

2. 解析失败不是链接的问题，是三件事同时发生：你填的 ae4456e3164821b38.app.workbuddy.host 是页面预览链接（对外 403，永远不可能是解析服务）；你部署的 wenjiang.oynana8023.workers.dev 在国内手机网络上被整段拦掉（超时）；公共代理（cors.lol / allorigins / codetabs / jina）在国内也基本不通。

第 1 条已经完全修好，并且有数据。第 2 条要分两半说：有解析服务时整条链路是通的（本报告第 7 张图就是真解析真生成）；没有服务、又不想花钱时，浏览器读不了别人的网页（同源策略），这是浏览器的硬限制，谁也绕不过去——所以我加了一条两步就能走通的路：打开原文 → 全选复制 → 切回 App 自动读进输入框。

2.3 快照被 Service Worker 锁死

原来的策略是 cache-first：先交缓存、后台再更新——但这次显示的还是上次那份。用户看到"更新于 03:49 是新时间、内容是旧的"，就是这么来的。现在改成网络优先（2.5 秒不回来才用缓存），SW 版本升到 wj-v30，旧缓存会在 activate 时清掉。

三、解析：三件事同时坏，逐个拆开

3.1 你填的那个地址，本来就不可能是解析服务

https://ae4456e3164821b38.app.workbuddy.host 是页面预览链接，浏览器直接打开就是 403「链接不完整」。它被存进配置后，每次取正文都要先陪它等十几秒超时——这就是"一直在转圈然后失败"。

现在改成先检测、再保存：检测不过的地址不写进配置；一条都不通就清空。启动 6 秒后还会静默体检一次，把已经失效的地址自动摘掉，并提示「已移除 1 条打不开的解析地址（HTTP 403）」。

3.2 workers.dev 在国内手机上就是连不上

你部署的 wenjiang.oynana8023.workers.dev 本身没问题，问题是 *.workers.dev 这个域名在国内经常整段被拦（截图里"超时没响应"就是这个）。这不是配置错误，换台机器也一样。

所以面板里现在直接写清楚这一点，并给了三条替代路：

1. 给 Worker 绑一个自己的域名（国内可达）；

2. 填 DeepSeek Key，用官方抓取接口（能直连、能抓公众号，约 5 元/1000 次）；

3. 什么都不配，用下面这条"打开原文 · 复制后自动读回"。

3.3 新增：打开原文 → 复制 → 切回来自动读进输入框

解析失败的弹层，第一顺位按钮改成了 「打开原文 · 复制后自动读回」：

  • 点它 → 用系统浏览器打开原文（不把当前编辑页跳走）；
  • 你在原文里长按全选 → 复制；
  • 切回 App → 自动读剪贴板，把正文填进输入框，顺手清掉「点击上方蓝字关注」「点赞在看」这类壳；
  • 浏览器不给自动读（部分机型），底部留一个「读进来」按钮，点一下就进。

这条路不需要服务器、不需要 Key、不需要翻墙，公众号、头条、小红书、知乎都一样有效。实测：贴一段 128 字的正文，点「读进来」，输入框立刻变成 text1:128，提示「已读回 128 字，直接点生成就行」。

3.4 有服务的时候，整条链路是通的（真跑给你看）

在带解析服务的环境下，用 IT之家的一篇真文章 https://www.ithome.com/0/803/511.htm 走完整流程：取正文 833 字（via corslol）→ 进编辑页 → 生成成稿成功，页面出现「复制全文」。全程 0 个 JS 报错。第 7 张图就是这一步的实拍。

四、还没做到的事（不糊弄）

1. 不部署、不填 Key、还要一键抓公众号正文 —— 做不到。浏览器不能读别人的网页，这是同源策略；国内又没有可用的免费公共解析服务（我实测了十几家国内免费 API，全部是 404 / 502 / 证书错误 / 硬盘写满）。能给的只有"两步走"和"花 5 块钱 1000 次"。

2. 头条热榜不是秒级，最快 15 分钟一次（GitHub Action 频率），页面会写明"缓存 · N 分钟前"。

3. 公共代理通道仍会抖，限流是它们那边的策略，我只能做多通道竞速 + 冷却 + 自动重试。
